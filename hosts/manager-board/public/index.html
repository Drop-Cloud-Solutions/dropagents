        Gates & pass-through steps

        These appear as agent: values in flow YAMLs but are engine-internal — nothing is spawned, so they have no persona, model, or provider to configure.

        wait-merged
        Parks until the operator clicks Merge PR (board or Telegram); the merge runs gh pr merge and resumes the flow.
        merge-auto
        Same park, no operator: the PR is merged automatically as soon as the post-commit hook has opened it. Swap it in for wait-merged in a flow to skip the merge approval. Manual Merge PR keeps working as a fallback.
        worktree-diff-review
        Pre-commit operator gate: parks for the diff-review modal; approve advances to commit, reject routes back to the developer.
        commit-auto
        Skips that pre-commit review: passes straight through to the commit step. Swap it in for worktree-diff-review to skip the commit approval.
        wait-action
        Generic operator park — Approve/Reject resumes it.
        commit-approval / merge-approval
        Lifecycle decision parks used by the staged flows.
        pr-ready / deploy-ready
        Pass-throughs that emit their lifecycle event and continue.
        run-script / verify / report-only
        Non-agent work: run a configured script / verify / report.
        merge (alias pr.merge), pr.open
        PR-gateway steps — open or merge the task's PR via the gateway.
        Model and persona changes apply on the next agent spawn — no restart needed. A provider change also applies live, but only if that backend was available when the orchestrator started; switching to a newly configured backend needs an orchestrator restart. A flow step with an explicit model: still wins for that step.
